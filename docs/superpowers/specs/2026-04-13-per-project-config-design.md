# Per-Project Config Design

## Summary

Add a per-project configuration file at `.veil/config.yaml` that controls credential scoping, scanner ignore patterns, and proxy host skipping. Generated by `veil init`, reconciled by a new `veil sync` command, and validated at startup by `veil run`.

## Motivation

Veil currently has no project-level configuration. This causes three friction points:

1. **Unscoped credentials require manual commands.** When `veil init` can't auto-detect hosts for a credential, the user must run `veil add --host` for each one individually. Five unscoped credentials means five manual commands.
2. **No way to exclude paths from scanning.** The only mechanism is `# veil:skip` inline comments in `.env` files. This requires editing files the user may not own (test fixtures, example files, vendored code).
3. **No way to skip hosts at the proxy layer.** Some services use certificate pinning and break under MITM. Internal dev servers don't need credential injection. Telemetry endpoints clutter the audit log. The only escape is the hardcoded `NO_PROXY=localhost,127.0.0.1,::1`.

A config file solves all three by letting users declare intent once and have every Veil command respect it.

## File Location

`.veil/config.yaml` inside the project state directory. This directory is already created by `veil init` and is gitignored.

## Schema

Three top-level keys. All are optional — an empty or missing config file changes nothing about current behavior.

### `scoping`

Maps credential names (exact match) to a list of allowed hosts. When present, overrides the auto-detected `AllowedHosts` for that credential.

```yaml
scoping:
  GITHUB_TOKEN:
    - api.github.com
  OPENAI_API_KEY:
    - api.openai.com
  SLACK_TOKEN:
    - slack.com
    - api.slack.com
```

- Keys must match credential names exactly as they appear in the vault (e.g., `GITHUB_TOKEN`, `mcp:slack:SLACK_TOKEN`).
- Values are string arrays of hostnames. Wildcard prefix matching (e.g., `*.github.com`) follows the same rules as the existing `AllowedHosts` field on `vault.Credential`.
- When a credential name appears in `scoping`, its hosts from the config replace any auto-detected hosts entirely — no merging.

### `ignore`

A list of glob patterns (relative to project root) for paths the scanner should skip during `veil init`.

```yaml
ignore:
  - "test/fixtures/**"
  - "*.example"
  - "vendor/**/.env"
```

- Patterns use standard glob syntax with `**` for recursive matching, via `github.com/bmatcuk/doublestar/v4`.
- Matching is checked before parsing — if a path matches any pattern, the file is skipped entirely.
- Patterns are relative to the project root. Absolute paths are rejected during validation.

### `skip_hosts`

A list of hosts the proxy passes through without interception. No MITM, no credential injection, no audit logging for traffic to these hosts.

```yaml
skip_hosts:
  - "*.internal.company.com"
  - "staging.local:8080"
  - "telemetry.example.com"
```

- Entries are merged into the `NO_PROXY` environment variable passed to the child process at `veil run` startup.
- Wildcard prefix matching (e.g., `*.example.com`) is supported, following `NO_PROXY` conventions.
- The hardcoded defaults (`localhost`, `127.0.0.1`, `::1`) are always included regardless of config.

## Validation

Config is validated when read. The following are errors that prevent the command from proceeding:

- Unknown top-level keys (catches typos like `scopping` or `skip_host`).
- Invalid glob syntax in `ignore` patterns.
- Absolute paths in `ignore` patterns.
- Non-string or empty values where strings are expected.

An empty config file or a file with only comments is valid.

## Command Behavior

### `veil init`

1. Reads `.veil/config.yaml` if it exists.
2. Applies `ignore` patterns to filter which `.env` files get scanned.
3. For each credential created: if the credential name has an entry in `scoping`, use those hosts instead of auto-detection.
4. After vaulting, generates or updates `.veil/config.yaml`:
   - If no config exists: writes a new file with all credentials pre-populated under `scoping` (using their resolved hosts), empty `ignore` and `skip_hosts` sections, and explanatory comments.
   - If config exists (`--force` re-init): merges new credentials into the existing `scoping` section. Existing entries are preserved. New credentials are appended. Stale entries (credentials no longer in vault) are left in place. `veil sync` is the dedicated tool for cleaning up stale entries.

### `veil run`

1. Reads and validates `.veil/config.yaml`.
2. Merges `skip_hosts` into the `NO_PROXY` env var for the child process.
3. Drift detection: compares `scoping` entries against vault contents. Prints warnings to stderr for:
   - Credentials in the vault with no `scoping` entry (uncovered).
   - `scoping` entries that don't match any credential in the vault (stale, e.g., after `veil remove`).
4. Warnings are non-blocking — the command proceeds normally. Drift warnings are suppressed when zero credentials are loaded (the zero-credential warning is sufficient on its own).

### `veil add`

1. Reads `.veil/config.yaml` if it exists.
2. If the credential name being added has an entry in `scoping`, applies those hosts as defaults. If `--host` flags are also provided, the flags take precedence (explicit user intent on a specific command overrides file defaults).

### `veil remove`

No config changes on remove. The credential's `scoping` entry becomes stale. This is detected by `veil run` (drift warning) and cleaned up by `veil sync`.

### `veil sync` (new command)

Reconciles `.veil/config.yaml` with the current vault state.

- Adds `scoping` entries for credentials that exist in the vault but aren't in the config (pre-populated with their current `AllowedHosts`).
- Removes `scoping` entries for credentials that no longer exist in the vault.
- Preserves all user-customized host lists for existing entries.
- Leaves `ignore` and `skip_hosts` sections untouched.
- Supports `--dry-run` to preview changes without writing.
- Prints a summary of additions and removals.

### `veil status`

No config-related changes. Future consideration: show config path and whether drift is detected.

## Config Generation

When `veil init` generates the config, it writes a commented YAML file:

```yaml
# Veil project config
# Docs: https://getveil.dev/docs/config

# Credential scoping — map credential names to allowed hosts.
# These override auto-detected hosts. Remove an entry to use auto-detection.
scoping:
  GITHUB_TOKEN:
    - api.github.com
  OPENAI_API_KEY:
    - api.openai.com
  SLACK_TOKEN:
    - slack.com
    - api.slack.com

# Scanner ignore — glob patterns (relative to project root) to skip during init.
# ignore:
#   - "test/fixtures/**"
#   - "*.example"

# Host skip list — hosts the proxy passes through without interception.
# skip_hosts:
#   - "*.internal.company.com"
```

The `scoping` section is populated with actual credentials and their resolved hosts. The `ignore` and `skip_hosts` sections are commented-out examples showing the syntax.

## What This Does Not Include

- **Global/user-level config.** Per-project only.
- **Pattern matching on credential names.** Exact name match only.
- **Hot-reloading.** Config is read once at command start.
- **`veil config` CLI subcommand.** Users edit the YAML directly.
- **Config migration/versioning.** No `version` field. Schema changes will be handled by backward-compatible additions.

## Implementation Notes

### New package: `internal/config`

The existing `internal/config` package handles path resolution. Config loading, parsing, and validation will be added here as new files (e.g., `config.go`, `config_test.go`) alongside the existing `paths.go` and `project.go`.

### YAML library

Use `gopkg.in/yaml.v3` for parsing. It supports round-trip comment preservation which is important for `veil sync` not destroying user comments.

### Integration points

- `scanner.Scan()` needs to accept ignore patterns and filter results.
- `vault.Credential.AllowedHosts` population in `cli/init.go` needs to check config scoping before falling back to auto-detection.
- `runner.buildChildEnv()` needs to merge `skip_hosts` into `NO_PROXY`.
- New `cli/sync.go` for the `veil sync` command.
- `proxy.New()` or `runner.Run()` needs to perform drift detection and emit warnings.
